# Instructions for agents integrating this SDK

Read the README and actual packaged interfaces before editing a consumer. This alpha is locally packable, not released or approved for production. `@arcdao` is a provisional scope whose availability/ownership is unverified. Never invent deployment addresses, chain readiness, uptime guarantees or mainnet approval.

Consumers require onboarding to the keeper's explicit allowlist. Public coordinator request acceptance and SDK installation do not guarantee fulfillment. Obtain approved deployment configuration and operator onboarding before live use; do not invent an onboarding API.

- Preserve game proof/payment -> exact-fee RNG request -> keeper proof -> authenticated callback -> deterministic candidates -> separate selection/mint. The dice example is only a starter and does not implement game economics or claim security.
- Read `requestFee()` from the pinned coordinator. Require the caller's exact fee before forwarding; helpers send the quote from the consumer balance. Do not accidentally subsidize underpayments with prefunded contract money or retain overpayment.
- Accepted onchain proof at or before requestedAt + 60 seconds is timely. Pending transactions, server events and callback arrival are not acceptance evidence. Expired unfulfilled requests can be refunded with `refundRequest(id)` only to their fixed refund address; failed native transfers become refund credit. Game-payment refunds are separate work.
- Authenticate callbacks using ArcVRFConsumer's immutable coordinator. Verify request ownership/existence. Callback receives the RAW bytes32 even for mapped requests; read getMappedResult or use canonical mapping. Store results; keep minting/transfers out of callback.
- Valid proof plus failed callback earns the fee. retryCallback retries only that SAME result; never request a reroll as recovery. Do not cancel before expiry or override a fixed key/input/mapping.
- Use canonical public helpers, not duplicate arithmetic or local modulo mapping. decodeEvidencePacket is decoding, not verification. replayCoordinator requires independently trusted receipt/block and state context: successful receipt, correct emitting coordinator/chain, request block hash, actual proof-acceptance block timestamp, fixed key/source signers/enabled mask/mapping, and event plus stored transcript equality. A packet alone proves none of those. Do not pass proof-supplied key or seed as trusted expectations.
- Always pass the actual deployment enabledSourceMask; default 7 is not a production activation recommendation. Stable source IDs and query derive from the request anchor. Never silently switch APIs, alter queries, truncate signed data or enable sources because they are in a catalog. Attestation is not proof of unbiased/immutable data.
- Known release issues include Seed V2 same-query response selection, public TS/Solidity attestation canonicality parity, source admission, crypto review, keeper readiness and actual chain/fee validation. Do not hide those behind successful packaging tests.
- Frontends import only the public package. Never add keeper, proof generation, fixture private keys, environment files, journal data or signer secrets to this package or a browser bundle. No public keeper API.
- No publishing, deployment or real-fund operations without explicit user authorization after release blockers are resolved. Never bypass the private flag or publish guard with ignore-scripts. A release must review guard removal and scope ownership.

Repository maintainers: build from the pinned `protocol/` snapshot. Its canonical upstream is https://github.com/d20dao/keeper. Review upstream changes and update snapshot/provenance together; do not independently change cryptographic or contract behavior as part of packaging. Run `npm ci` and `npm test`; publishing remains blocked.
